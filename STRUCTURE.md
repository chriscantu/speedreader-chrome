# Repo structure

Reference for what lives where. Linked from [`CLAUDE.md`](./CLAUDE.md); update whenever a directory is added, removed, or renamed.

For the project's purpose, hard constraints, and ways of working, see [`CLAUDE.md`](./CLAUDE.md). For the platform-agnostic / Chrome-specific boundary contract, see [`src/core/README.md`](./src/core/README.md).

## Top level

```
.
├── src/                      # All TypeScript source
├── docs/                     # Specs, ADRs, design pack, decisions
├── icons/                    # Extension icons (16/48/128)
├── fonts/                    # Bundled font binaries (hash-pinned) + OFL.txt
├── bin/                      # Build / CI gate scripts (e.g. verify-font-integrity.sh)
├── hooks/                    # Claude Code harness hooks
├── scripts/                  # One-off issue / label / milestone scripts
├── .claude-plugin/           # Harness plugin config (generated by `harness sync`)
├── .github/workflows/        # GitHub Actions CI
├── CLAUDE.md                 # AI assistant + contributor context (root pointer)
├── CONTRIBUTING.md           # Commit / branch / PR conventions
├── PRINCIPLES.md             # Project principles
├── README.md                 # User-facing project intro
├── STRUCTURE.md              # This file
├── Plans.md                  # Harness task-tracking stub (issues live in GH)
├── harness.toml              # Harness v4 project config
├── manifest source           # See `src/chrome/manifest.ts`
├── package.json              # npm scripts: dev / build / lint / format / test
├── tsconfig.json             # TS compiler config
├── vite.config.ts            # Vite build config
├── vitest.config.ts          # Vitest test runner config
├── eslint.config.js          # ESLint flat config
└── .prettierrc               # Prettier config
```

Build output (`dist/`, `out/`, `build/`) is gitignored; harness runtime state (`.claude/memory|sessions|state`) is gitignored per [`.gitignore`](./.gitignore).

## `src/` — platform split

The source tree is split along the platform boundary. **One-way dependency**: `src/chrome/` may import from `src/core/`; the reverse is forbidden.

```
src/
├── core/                     # Platform-agnostic engine (no chrome.* / browser.*)
│   ├── README.md             # Boundary contract — required reading
│   ├── __tests__/            # Core-wide smoke tests
│   ├── tokenize/             # Pure text → RSVP token stream
│   ├── orp/                  # Optimal Recognition Point (focus character)
│   ├── rsvp-engine/          # Word emission cadence (WPM → setTimeout)
│   └── settings/             # Zod schema + defaults + version migrations
├── chrome/                   # Chrome MV3-specific glue
│   ├── manifest.ts           # Generates manifest.json at build time
│   ├── background/           # Service worker entry
│   ├── content/              # Content script entry (lazy-injected)
│   ├── popup/                # Browser-action popup (HTML + TS)
│   ├── options/              # Options page (HTML + TS)
│   └── settings/             # chrome.storage.sync adapter over core/settings
└── icons/                    # (build-time icon staging, if used)
```

### `src/core/` modules

Each module ships as `<module>/{<module>.ts, index.ts, __tests__/}`. The `index.ts` is the public re-export surface — consumers import only from `index`.

| Module | Public surface | Tests |
|---|---|---|
| `tokenize/` | `tokenize(text: string): string[]` (emits words + structural sentinels `\n\n`, `—`, `–`) | `tokenize.test.ts` |
| `orp/` | `orp(word): number`, `splitWordAtFocus(word): {before, focus, after}` | `orp.test.ts` |
| `rsvp-engine/` | `createRsvpEngine({words, wpm})` → `{state, start, pause, resume, stop, setWpm, subscribe}` | `rsvp-engine.test.ts` |
| `settings/` | `SettingsSchemaV1`, `DEFAULT_SETTINGS`, `migrate`, `CURRENT_VERSION` | `schema.test.ts`, `migrations.test.ts` |

### `src/chrome/` entry points

| Path | Role |
|---|---|
| `manifest.ts` | Generates the MV3 `manifest.json` (single source of truth — no checked-in JSON) |
| `background/index.ts` | Service worker — message routing, lazy content-script injection |
| `content/index.ts` | Content script — DOM extraction + overlay mount |
| `popup/index.{html,ts}` | Browser-action popup |
| `options/index.{html,ts}` | Full-tab options page |
| `settings/storage.ts` | Wraps `chrome.storage.sync`; uses `src/core/settings/` for schema |

## `docs/`

```
docs/
├── superpowers/
│   ├── specs/                # Specifications (SSOT — "specs ship as PR first")
│   ├── plans/                # Implementation plans (per-issue)
│   └── decisions/            # Lightweight decision notes (subordinate to ADRs)
├── adrs/                     # Architecture Decision Records (NNNN-<slug>.md)
├── design/                   # Hi-fi mocks (HTML + PNGs) + RECONCILIATION.md
└── permission-justifications.md  # Manifest permissions rationale (store-listing input)
```

### Conventions

- **Specs are SSOT.** When `docs/superpowers/specs/*.md` and the code disagree, the spec leads. Implementation PRs may not land before the corresponding spec PR. See `feedback_specs_ship_as_pr_first.md` in the project's harness memory.
- **ADRs follow** `NNNN-<kebab-title>.md` and the canonical format (Date / Responsible Architect / Author / Contributors / Lifecycle / Status / Context / Decision / Consequences). The `/adr` skill scaffolds new ones.
- **Hi-fi design pack** (`docs/design/Speed Reader Hi-Fi.html`) is the visual contract for the overlay; CSS tokensets and theme names defined there are load-bearing for `src/chrome/content/` apply-layer work and #74's theme tokenset scope.

## `hooks/` and `.claude-plugin/`

Generated and managed by [Claude Code Harness](https://github.com/chriscantu/claude-code-harness-marketplace) v4. Run `harness doctor` to verify, `harness sync` to regenerate `.claude-plugin/` from `harness.toml`. Do not hand-edit `.claude-plugin/`.

## `bin/`

Build / CI gate scripts with companion vitest coverage (e.g., `verify-font-integrity.sh`). Distinct from `scripts/`, which houses one-off GitHub project plumbing. Invoked by CI via `npm run verify:fonts` and friends.

## `scripts/`

One-off bash scripts for GitHub project setup (labels, milestones, bulk issue creation). Not part of the build; not invoked by CI. See the script source for usage.

## `.github/workflows/`

CI runs on pull requests and pushes to `main` across Node `20.x` and `22.x`: `npm ci` → `lint` → `format:check` → `test` → `verify:fonts` (source pins) → `build` → `verify:fonts --check-dist` (dist emission). Every step is a PR-blocking gate. See [`.github/workflows/ci.yml`](./.github/workflows/ci.yml).

## `Plans.md`

The Harness task-tracking file expects per-task rows. SpeedReader uses GitHub Issues as the SSOT instead, so `Plans.md` is a stub pointing at the issue tracker. Harness skills that read `Plans.md` resolve the file but find no rows — by design.

## Naming and renaming

If you add or rename a directory:

1. Update this file in the same PR.
2. If the change crosses the `src/core/` ↔ `src/chrome/` boundary, also update [`src/core/README.md`](./src/core/README.md).
3. If the change touches the spec / ADR / decision conventions, update [`CLAUDE.md`](./CLAUDE.md) too.
